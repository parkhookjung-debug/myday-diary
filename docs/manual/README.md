# 사용자 설명서 원본과 갱신 방법

[웹에서 전체 설명서 읽기](../USER-MANUAL.md) · [Word 파일 받기](MyDay-0.12.0-User-Manual.docx) · [프로젝트 첫 화면](../../README.md)

앱 0.12.0과 2026년 10월 28일 기준으로 작성한 36개 장의 상세 사용 설명서입니다. Windows·Mac·Android 사용 순서, 각 기기의 차이, 실제 기능 화면, 성장·수집 규칙, 백업과 복구, 로컬 채팅, 오류 해결을 설명합니다. 부록에는 일기 형식 100종, 상몬 64종, 소품 모양과 수정할 파일을 실었습니다.

## 어떤 파일을 수정하나요

| 파일 | 용도 |
| --- | --- |
| [user-manual-content.json](user-manual-content.json) | 본문·절차·표·그림·링크를 관리하는 원문 |
| [build-user-manual.py](../../tools/build-user-manual.py) | 동일한 원문에서 Markdown과 Word를 만드는 도구와 문서 서식 |
| [USER-MANUAL.md](../USER-MANUAL.md) | GitHub에서 읽는 생성 결과 |
| [MyDay-0.12.0-User-Manual.docx](MyDay-0.12.0-User-Manual.docx) | 공유하고 편집하는 Word 생성 결과 |

원문 JSON을 수정한 뒤 저장소 최상위에서 생성합니다. Python 3와 `python-docx`, `Pillow`가 필요합니다. 아래 명령은 앱 실행이나 서버 배포를 하지 않고 문서 두 파일만 갱신합니다.

```sh
python tools/build-user-manual.py
```

임의 폴더에서 실행할 때는 `--root`로 저장소 절대 경로를 지정합니다. Word에서 직접 수정한 내용은 다음 생성 때 덮어쓰므로 원문에도 반영해야 합니다. 버전·날짜·소스 커밋을 바꿀 때는 생성 도구의 표지와 Markdown 메타데이터도 함께 갱신합니다.

## 수정 후 확인

1. 기능 규칙은 실제 코드와 shared 공통 원본을 기준으로 확인합니다. 구현하지 않은 기능이나 실기기에서 아직 점검하지 않은 항목을 구현 완료로 쓰지 않습니다.
2. 목록 수, 점수, 확률, 파일 제한, 세 운영체제의 조작 차이를 대조합니다.
3. Markdown의 목차와 그림·문서 링크를 확인합니다.
4. Word를 PDF와 페이지 이미지로 렌더링하여 모든 페이지의 글자·표·그림·목차와 페이지 번호를 확인합니다. Word의 필드는 열 때 갱신되며 문서 편집 후에는 목차의 페이지 번호도 다시 갱신합니다.
5. 원문·생성 도구·Markdown·Word를 함께 커밋합니다. 검사용 PDF·페이지 이미지는 저장소에 넣지 않습니다.

화면 예시는 `previews/`의 테스트 자료를 사용합니다. 실제 개인 일기, PIN, 백업, 채팅 초대코드는 설명서에 추가하지 않습니다. 실행파일의 출처와 검증 범위는 [0.12.0 빌드 기록](../builds/myday-0.12.0.json)을 참고하세요.

## 이번 문서 확인 결과

2026년 10월 28일 기준으로 Word 53쪽 전체의 페이지 배치를 확인했습니다. 36개 장·54개 표·7개 실제 화면을 포함하며, 목차 36개와 로컬 문서·그림 링크를 검사했습니다. 부록의 일기 형식 100개, 상몬 64개, 소품 모양 50개를 현재 자산 목록과 대조했습니다. 페이지 수는 Word 버전이나 설치된 글꼴에 따라 달라질 수 있습니다. 앱 코드는 이번 문서 작업에서 변경하지 않았습니다.
